# Изменения

## 1.0.0 — 2026-11-09

Между Claude Code и `pyrefly lsp` теперь стоит прослойка `scripts/pyrefly_lsp_proxy.py`
(Python, без зависимостей). Что изменилось для Claude по сравнению с 0.1.0 — замеры в условиях
Claude Code 2.1.319 с pyrefly 1.4.1 (как мерили — в README):

| | 0.1.0 | 1.0.0 |
|---|---|---|
| Первый поиск ссылок после открытия файла | 14 в 1 файле | 718 в 57 файлах |
| Исходящие вызовы `await f()` и `f() + g()` | теряются | полные |
| Функция, дописанная мимо Claude в неоткрытый файл | не видит, ложная ошибка | видит |
| Открытый файл, изменённый мимо Claude | старый текст | новый текст |
| git worktree без своего `.venv` | библиотек не видит | библиотеки из `.venv` основной копии |

- Поиск ссылок полный с первого запроса: индексация `lazy-blocking`.
- Исходящие вызовы полные: прослойка достраивает вызовы, которые pyrefly теряет внутри `await`
  и выражений (facebook/pyrefly#5486).
- Сверка с диском: файлы, изменённые мимо Claude, видны серверу со следующего запроса; открытые
  документы получают текст с диска. Отслеживаются и конфиги, которые pyrefly переносит в режиме
  auto: `mypy.ini`, `setup.cfg`, `pyrightconfig.json`.
- git worktree без своего `.venv` берёт интерпретатор и `pyrefly` основной копии.
- `pyrefly` ищется в `.venv` проекта, затем в PATH; без него — понятная ошибка вместо падения.
- Настройки плагина: режим проверки для проектов без конфига, отключение ошибок, путь к pyrefly,
  предел индексации, выключатели сверки с диском и достройки исходящих вызовов.
- Прослойка запускается как `python3 -I`: файлы проекта и `PYTHONPATH` не подменяют её модули.
- `workspaceFolder` и `startupTimeout` в конфиге сервера.
- Тесты: модульные на прослойку и сквозные с настоящим pyrefly.
